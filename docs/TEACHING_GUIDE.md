# 授课建议

## 推荐顺序

不要一开始就让学员只看完整复合问题。先用同一个症状问题分别运行单一检索器，让差异变得可见；最后再进入综合模式。

| 阶段 | 建议模式 | 学员应观察 |
|---|---|---|
| 1 | TF–IDF | 查询如何进入固定词表；完整向量怎样归一化、逐维相乘并形成余弦分数 |
| 2 | BM25 | DF/IDF、词频饱和与长度归一化怎样共同形成每个词项的贡献 |
| 3 | 语义向量 | 离线文档向量如何进入 FAISS；完整稠密向量怎样点积并回收 Top-K |
| 4 | 属性图 | 语义锚点如何落到实体；图模式、关系方向与跳数怎样让候选集合逐层收缩 |
| 5 | RDF | 领域 ID 如何成为 IRI；变量怎样沿三元组模式绑定并经过字面量过滤 |
| 6 | SQL | 物理行怎样过滤；主外键值怎样配对成逻辑连接行，再完成分组计数 |
| 7 | 综合路由 | 一个复合问题如何拆成不同证据责任 |

## 单一模式演示

先输入：

> 大豆叶片出现褐色近圆形病斑，最可能关联哪些病害？

分别运行 TF–IDF、BM25 和语义向量。要求学员记录：

1. 查询被拆成了哪些词。
2. 查询表示是稀疏还是稠密。
3. 排名分值表示什么。
4. 该检索器能否可靠回答“共有多少例”。

语义向量模式应额外区分两个时间阶段：

- 入库阶段：文本块批量 Embedding，建立并持久化 FAISS 索引。
- 查询阶段：只对问题做 Embedding，再通过索引返回行号和分数。

可以先调用 `/api/v1/document-index/status` 查看 228 个向量是否已经入库，再运行查询观察前端的“文档向量索引”阶段。

每轮查询都建议先让播放器自动运行一遍，再由教师点击阶段名称逐帧复盘。播放器只在一个主舞台显示当前过程，避免学员同时面对多组数字：

- TF–IDF 先观察 110 维词表只有部分坐标被点亮，再选择候选文档，核对同坐标乘积如何进入分子。
- BM25 切换候选文档，观察长度压力和词频饱和如何改变同一查询词的贡献；不要把它误讲成余弦相似度。
- 语义检索观察文本进入编码器、192 个稠密坐标形成、探针进入 FAISS，再核对查询/文档分组乘积。
- 属性图先在三维语义空间选择锚点，再看允许的图模式；逐跳暂停，要求学员口述输入集合、关系方向、过滤条件和输出集合，最后再阅读 Cypher。
- RDF 先区分 Class、Property、IRI、Literal，再观察变量槽沿三元组模式绑定及安全间隔期闸门。
- SQL 检索先观察 240 个物理行粒子依次通过筛选门，再看相同键值如何合并为逻辑连接行，最后进入 `GROUP BY` 桶。
- 生成阶段观察问题、结构化结果和证据卡片进入上下文窗口，再由 LLM 输出回答。

然后在属性图中输入：

> 2025年7月六合区的大豆病例中，出现褐色近圆形病斑时最可能是什么病，还伴随哪些症状？

在 RDF 中输入：

> 大豆褐斑病推荐哪种安全间隔期不超过14天的药剂，依据来自哪里？

在 SQL 中输入完整的地区、月份、症状和药剂约束，重点解释查询参数如何映射到表连接。

## 复合问题演示

最后在“综合路由”中输入完整问题。可以逐阶段暂停：

1. **任务分解**：先确认问题里有实体对齐、计数、邻域和数值约束四种责任。
2. **实体锚点**：观察自然语言症状和图节点的相似度。
3. **参数化 SQL**：确认时间采用左闭右开区间，用户值没有拼接进代码。
4. **聚合结果**：明确“总匹配 24 例”和“主要病害 18 例”不是同一个数字。
5. **局部子图**：观察伴随症状从哪些病例关系中统计而来。
6. **SPARQL**：观察安全间隔期 `<= 14` 是图中的数据属性过滤。
7. **证据合并**：讨论冲突时为何精确计数以关系数据库为准。
8. **证据约束生成**：区分“检索得到事实”和“模型组织语言”。

最后一步必须保留。若模型接口已配置，界面显示模型名称和“LLM + 检索证据”；若未配置或接口失败，界面显示“本地模板代替 LLM”。这正好用于解释：RAG 的检索层和生成层可以独立失败与回退，不能因为有一段自然语言结果就宣称调用了 LLM。

## 建议课堂练习

- 把“褐色近圆形病斑”改写为“接近圆形的棕褐色斑点”，比较三种文档检索。
- 把时间改成 2025 年 6 月，预测 SQL 参数和结果如何变化。
- 把安全间隔期从 14 天改成 6 天，观察药剂查询是否仍有命中。
- 删除一个属性图关系后重新运行，区分“节点存在”和“路径可达”。
- 要求学员设计一个新的白名单 action，而不是让模型自由生成整段查询。

所有病例、诊断、药剂与安全间隔期都是教学模拟数据，课堂上应持续保留这一边界。

## 从教学样例过渡到学员项目

完成七种内置模式后，再让学员进入“数据工作区”。推荐按三次实验组织：

### 实验一：把一组文档变成三种索引

1. 准备 2–5 个同一领域的 TXT、PDF 或 Word 文档。
2. 先预测 700 字目标长度、100 字重叠会产生多少块，再上传观察真实数量。
3. 在构建流水线暂停讲解：原文和 Chunk 是事实层；词法统计、向量和 FAISS 是派生索引，删除后可以重建。
4. 用同一个问题分别运行 TF–IDF、BM25、Semantic，比较证据而不是只比较最终回答。
5. 改写问题中的同义表达，观察词法命中与语义命中的差异。
6. 配置真实 Embedding 后新建另一个工作区；强调不能把旧索引和新模型查询向量混用。

要求学员提交工作区目录结构说明，并能回答：为什么 FAISS 不能代替 `chunks.jsonl`？为什么分块属于入库阶段而不是每次查询阶段？为什么 Embedding 模型发生变化就必须重建索引？

### 实验二：把业务表变成只读 SQL RAG

1. 准备一张列名有业务含义的 CSV / Excel，例如地区、日期、作物、产量、症状。
2. 上传后对照 `schema.json`，解释“业务字段名”与 `c_001` 物理列的映射。
3. 先关闭 LLM 规划，练习计数、过滤、平均、最大值；观察确定性规划器能覆盖哪些表达。
4. 再启用 LLM 规划，比较候选 SQL，但要求学员逐项核对参数、表边界、执行计划和结果行。
5. 尝试提示模型修改表或读取其他表，确认静态检查、`query_only` 与 SQLite authorizer 会拒绝。

这里要把“模型生成 SQL”和“数据库允许执行 SQL”严格分开。工程系统的安全性不能依赖提示词服从；提示词只是规划质量层，确定性验证与数据库 VM 权限才是执行边界。

### 实验三：把 JSON 图变成属性图 RAG

1. 先不要上传。让学员在图数据页阅读容器、NODE、EDGE 三个示例，并下载 `graph.json`。
2. 用 3–8 个节点构造最小图，要求至少包含两个节点类型、两种关系和一份 `documents` 证据；先手工检查每条边的 source/target。
3. 故意把一条边指向不存在的 ID，观察构建任务在校验阶段失败且工作区不发布；再修复后重传。
4. 打开 `graph.sqlite3`，分别查看节点表、边表和两个 evidence 关联表；说明事实存储与向量索引是两层结构。
5. 打开 `node_cards.jsonl`，对照源节点观察“节点 + 局部关系”如何形成 Embedding 输入；说明为什么边本身没有单独进入 FAISS。
6. 在实验台用自然语言查询：先暂停在三维锚点空间，再观察关系白名单如何收缩为 SQLite 参数化邻接查询，最后逐跳播放局部子图。
7. 删除 `documents` 但保留节点描述再建一个工作区，比较“能找到节点”和“能给出高质量可核验依据”的区别。

要求学员能回答：FAISS 为什么返回的是节点行号而不是图路径？SQLite 邻接索引为什么比穷举全部边更可控？为什么 `evidence_ids` 不属于装饰字段？为什么这一条自建图链不需要连接 Neo4j、也不会污染已有 Neo4j 数据库？

### 连接微调课程

在“模型连接”中选择本地模型时，可以直接把主输入框指向完整 Hugging Face 模型，也可以直接指向 LoRA 课程产生的 `outputs\run_xxx`。后一种方式让学员观察平台如何从 `adapter_config.json` 找到基础模型，再执行“基础权重 + Adapter”的组合加载。只有目录关系被移动破坏时，才使用高级输入框分别指定基础模型和 Adapter。

先用 0.5B 模型完成链路核验，再讨论 7B 模型带来的显存、精度、加载时间和吞吐变化。“保存并加载测试”会真实加载权重并完成一次短生成；因此测试通过意味着目录识别、Transformers、PEFT、设备、精度和生成链都已经贯通，而不只是文件存在。

当前版本按“一名学员一套本机后端”设计。若课堂共用一台服务器，应先增加账号、租户与配额，而不是让不同学员在同一运行时配置中互相覆盖 Key 和工作区。
