## 一、这个项目的教学意义

各位同学，这个项目不是只演示一次检索，而是让大家直观看见 RAG 从用户输入到最终回答的完整过程：

```text
用户问题
  → 问题解析
  → 检索私有知识库
  → 计算相关度或生成查询语句
  → 回收 Top-K 证据
  → 将问题与证据交给大模型
  → 生成有依据的回答
```

在实验台中，大家可以观察：

- TF-IDF 如何构建查询向量并计算余弦相似度；
- BM25 如何计算词项权重并得到文档得分；
- 语义向量如何完成 Embedding、向量相似度计算和 Top-K 排序；
- 属性图如何找到语义锚点、沿关系扩展并回收子图证据；
- RDF 如何通过三元组和 SPARQL 查询知识；
- 关系型数据库如何生成受约束 SQL、执行查询并返回表格证据；
- 大模型如何基于检索结果生成最终回答。

这个项目的核心不是“让大模型记住知识”，而是让模型在回答前先查询外部知识库。

## 二、源码为什么全部提供

项目源码已经完整提供给大家。希望大家先把项目跑通，再根据自己的研究方向继续改造，例如：

- 替换成自己的论文、实验记录或业务文档；
- 替换成自己的 Excel、CSV 或关系型数据；
- 设计自己的领域本体、节点类型和关系类型；
- 修改检索策略、提示词、查询约束和界面；
- 最终形成支持自己研究工作的 RAG 工具。

建议按照下面的顺序推进：

```text
先使用内置数据理解流程
  → 上传自己的数据构建工作区
  → 检查检索证据是否正确
  → 修改领域结构与提示词
  → 最后再扩展算法和功能
```

## 三、界面布局

页面顶部包含三个入口：

| 入口 | 作用 |
|---|---|
| 实验台 | 选择知识库和 RAG 方法，输入问题，观察检索与生成全过程 |
| 数据工作区 | 上传自己的文档、表格或图数据，构建独立私有知识库 |
| 模型连接 | 配置远程 API，或者加载本地完整模型与 LoRA Adapter |

## 四、数据工作区是什么

数据工作区负责把原始文件转换为可以检索的知识库。

这里的“私有知识库”不是重新训练大模型，而是把自己的数据保存为索引、数据库或图结构。用户提问时，系统先查询这些数据，再把检索到的证据交给大模型。

### 1. 文档检索库

支持上传 `txt`、`md`、`pdf`、`docx`、`html` 等文档。

系统会自动完成：

```text
原始文档
  → 文本解析
  → 自动分块 Chunk
  → TF-IDF / BM25 词法索引
  → Embedding
  → FAISS 向量索引
```

“目标分块长度”决定每个文本块的大致长度；“相邻重叠长度”用于保留跨文本块的上下文。初次使用可以保留默认值。

### 2. 关系数据库

支持上传 `CSV` 或 `Excel`。

系统会自动读取表头、推断字段类型，并构建 SQLite 数据库：

```text
CSV / Excel
  → 表头识别
  → 字段类型推断
  → SQLite 建表与入库
  → 生成受约束的只读 SQL
  → 返回查询结果
```

上传前应尽量保证：

- 第一行是字段名；
- 一列只表达一种含义；
- 日期、数字和文本格式尽量统一；
- 不要在同一个单元格中混入多个复杂对象。

### 3. 属性图工作区

支持上传 `graph.json` 或 `graph.jsonl`。

图数据至少要明确：

- `nodes`：节点，必须有 `id`、`type`、`name`；
- `edges`：边，必须有 `source`、`target`、`type`；
- `properties`：节点或边的附加属性；
- `documents`：可选的证据文档；
- `evidence_ids`：把节点、边与原始证据关联起来。

系统会自动完成：

```text
JSON / JSONL
  → 节点与边校验
  → 构建本地属性图
  → 生成节点语义卡
  → 建立节点 FAISS 索引
  → 语义锚点检索
  → 最多两跳的受约束关系扩展
```

### 4. 本项目与常见 RAG 项目的区别

很多公开项目只提供“文档切块 + 向量检索”。本项目在同一套教学系统中同时提供：

- 文档 RAG：TF-IDF、BM25、语义向量；
- 关系数据库 RAG：Schema、SQLite、SQL；
- 属性图 RAG：节点 Embedding、关系扩展、子图证据；
- 内置 RDF/SPARQL RAG 演示。

因此，大家能够比较不同数据结构适合解决什么问题，而不是把所有知识都强行转换成文档向量。

### 5. 使用自己的数据构建知识库

操作顺序如下：

1. 打开“数据工作区”。
2. 选择“文档检索库”“关系数据库”或“图数据工作区”。
3. 填写工作区名称。
4. 上传符合要求的文件。
5. 点击“构建并发布工作区”。
6. 等待校验、入库和索引构建完成。
7. 在“已发布工作区”中点击“打开”。
8. 回到实验台输入问题并检查检索证据。

每个工作区拥有独立的数据文件、索引和数据库，不会与其他学员的数据混在一起。

## 五、模型连接：远程 API

### 1. API 是什么

API 可以理解为本项目调用远程大模型服务的接口。

```text
RAG 后端
  → 通过 HTTPS 发送 JSON 请求
  → API Base 指向的模型服务器
  → 远程模型完成推理
  → 返回 JSON 响应
  → 前端显示最终回答
```

RAG 系统通常会把“用户问题 + Top-K 检索证据”一起发送给生成模型。如果配置了远程 Embedding，文档块或节点语义卡还会被发送到 Embedding 接口生成向量。

### 2. 四个主要配置项

| 配置项 | 含义 |
|---|---|
| API Base | 模型服务的网络地址，可填写 `/v1` 地址，也兼容完整的 `/chat/completions` 地址 |
| API Key | 身份认证和计费凭证，通常以 `sk-` 开头 |
| 生成模型 | 负责根据问题和证据生成回答的模型名称 |
| Embedding 模型 | 负责把文本转换成向量的模型名称，可选 |

### 3. API 如何获取

优先从模型服务商的官方控制台注册、充值并创建 API Key。

也可以在淘宝等平台购买兼容 API 中转服务，但只建议用于教学测试。购买前应确认：

- 是否兼容 OpenAI API 格式；
- API Base 和模型名称应该怎样填写；
- 是否支持 `/chat/completions` 和 `/embeddings`；
- 请求内容是否会被保存；
- 计费方式、并发限制和有效期。

不要把 API Key 发到群里、上传到公开仓库或放进截图。研究数据涉及隐私时，优先使用官方服务或本地模型。

### 4. API 配置步骤

1. 打开“模型连接”。
2. 选择“OpenAI 兼容 API”。
3. 填写 API Base、API Key 和生成模型。
4. 如需远程语义向量，再填写 Embedding 模型。
5. 勾选“启用证据约束生成”。
6. “启用 LLM 查询规划”主要用于通用表数据，可按需开启。
7. 点击“保存并加载测试”。
8. 状态显示 `READY` 后回到实验台。

如果只配置生成模型、不配置远程 Embedding，系统仍可使用内置的本地编码器演示向量检索。

## 六、模型连接：本地模型与 LoRA Adapter

### 1. 本地完整模型

本地模型是已经下载到电脑中的完整 Hugging Face 模型目录，通常包含：

```text
config.json
tokenizer.json 或 tokenizer.model
tokenizer_config.json
model.safetensors 或分片权重
```

未使用微调模型时，只填写完整模型目录即可，“独立 LoRA Adapter 目录”保持为空。

示例：

```text
C:\Users\用户名\Downloads\LoRA-Visual-Lab\lora-visual-lab\backend\models\Qwen2.5-0.5B-Instruct
```

### 2. Adapter 是什么

LoRA 微调一般不会修改原始基础模型，也不会重新保存一套完整模型。它训练并保存的是一组较小的增量参数，这组增量参数就是 **LoRA Adapter**。

```text
基础模型权重 + LoRA Adapter 增量权重 = 微调后的推理效果
```

Adapter 不能脱离对应的基础模型单独推理。其目录通常包含：

```text
adapter_config.json
adapter_model.safetensors
```

### 3. 如何找到 Adapter 路径

在 LoRA 微调项目中，每次训练产生的输出目录就是 Adapter 目录，例如：

```text
C:\Users\用户名\Downloads\LoRA-Visual-Lab\lora-visual-lab\backend\outputs\run_8b0aca5164f7
```

也就是说：

- `backend/models/模型名称`：基础模型；
- `backend/outputs/run_xxx`：本次 LoRA 微调生成的 Adapter。

### 4. 三种配置方式

#### 未使用微调模型

```text
模型或微调输出目录：填写基础模型目录
独立 LoRA Adapter 目录：留空
```

#### 使用微调后的模型：显式指定

```text
模型或微调输出目录：填写基础模型目录
独立 LoRA Adapter 目录：填写 outputs/run_xxx
```

#### 使用微调后的模型：自动识别

```text
模型或微调输出目录：直接填写 outputs/run_xxx
独立 LoRA Adapter 目录：留空
```

自动识别模式会读取 `adapter_config.json`，并尝试在微调工程的 `backend/models` 中定位对应的基础模型。

计算设备和权重精度初次使用均选择“自动”。保存后点击“保存并加载测试”，确认页面显示基础权重、Adapter 路径和 `READY`。

## 七、最终需要理解的主线

```text
自己的数据
  → 构建私有知识库
  → 选择合适的检索方式
  → 回收可检查的证据
  → 远程 API 或本地模型
  → 生成最终回答
```

RAG 的价值不只是提高回答效果，更重要的是让大模型能够使用自己的数据，并让回答过程可以检索、检查和继续改造。
